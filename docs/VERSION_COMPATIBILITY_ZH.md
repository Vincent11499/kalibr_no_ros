# 版本兼容说明

软件发布版本、项目文档 schema 和标定行为不是同一个概念，后续分别演进。

| 版本 | 当前值 | 用途 | 何时升级 |
|---|---:|---|---|
| 软件版本 | `1.1.0` | CLI、安装包与发布说明 | 每次正式软件发布 |
| 配置 schema | `1.0.0` | task、初始化、机器 workflow 与 profile | 字段结构或解释发生不兼容变化 |
| 数据集 schema | `1.0.0` | `dataset.yaml` | 目录清单结构或语义发生不兼容变化 |
| 结果 schema | `1.0.0` | 标定结果、manifest、报告数据 | 结果结构或语义发生不兼容变化 |
| 状态 schema | `1.0.0` | 机器断点续跑状态与输入哈希缓存 | 状态结构发生不兼容变化 |
| `calib_params` schema | `1.0.0` | 机器汇总参数和跨电脑复用 | 汇总文件结构或语义发生不兼容变化 |
| 标定行为版本 | `1.0.0` | 判断历史结果能否复用 | 数学模型、默认值、数据选择或坐标语义变化 |

当前版本按以下规则处理：

1. 新生成文档一律写各自的规范 schema `"1.0.0"`。
2. 读取时接受字符串 `"1.0.0"`，也接受 v1.1.0 初期曾误写但结构未改变的
   `"1.1.0"`；后者只是兼容别名，不是新的格式。
3. 整数 `1`、浮点数 `1.0` 和未知字符串不接受，不能只改版本号绕过结构校验。
4. 同一主版本内如确需结构迁移，应增加显式、逐级迁移函数，并在读回验证语义后写成
   当前规范版本，不能把任意 `1.x` 自动当作相同格式。
5. 机器工作流根据标定行为版本、数据集指纹、profile 语义哈希、任务依赖和受管结果
   清单共同决定续跑或重算。软件补丁、安装前缀、YAML 排版和兼容 schema 别名不会
   单独触发重标定。旧状态若还没有语义哈希，而 profile 文件字节又同时发生变化，
   程序无法从旧哈希证明二者等价，会保守重算一次；续跑后新状态会记录语义哈希。
6. 数据集旧缓存只有在保存了结构文件内容 SHA-256 且能绑定既有成功交付时才无求解
   迁移；仅有路径、大小、mtime/ctime/inode/device 的旧缓存无法证明历史 CSV 内容，
   对应阶段会自动重标定一次。图像不补算内容哈希，仍以清单、时间戳和大小校验。
7. 标定行为版本不相同，或无法证明 profile/输入/依赖语义相同时，采用保守策略重算，
   不静默复用历史结果。

因此，升级软件不要求同步改写数据集和现场配置版本；只有对应文档格式真的变化时，
才升级该 schema。发布说明必须分别列出软件版本、各文档 schema 与标定行为版本。
