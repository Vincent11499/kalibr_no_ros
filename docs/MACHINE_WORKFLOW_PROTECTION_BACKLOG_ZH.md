# 机器工作流防护暂缓清单

## 1. 当前阶段

项目仍处于算法测试与收敛验证阶段。为允许在同一批次内反复调整程序、模式、模板和
数据，`machine_workflow.py` 当前固定使用：

```python
_STRICT_PROVENANCE = False
```

这不是产线放行配置。当前行为是发现跨次运行 provenance 变化后，更新 binding 并通过
既有安全重标定流程重跑受影响阶段，不再要求仅因这些变化创建新批次。

## 2. 当前暂缓的严格防护

| 暂缓项 | 测试阶段行为 | 产线恢复目标 |
|---|---|---|
| 软件发布版本、commit、source/build fingerprint、构建类型和关键实现文件哈希必须一致 | 切换新旧版本后重跑所有当前存在的数据阶段 | 任一变化拒绝复用，要求新批次 |
| `stereo.mode` 必须一致 | 变化后重跑双目及其 Camera–IMU、BaseLink 下游 | 模式变化要求新批次 |
| `stereo_imu.mode` 必须一致 | 变化后重跑 Camera–IMU | 模式变化要求新批次 |
| `stereo_imu.recompute_extrinsics` 必须一致 | 变化后重跑 Camera–IMU | 活动参数变化要求新批次 |
| Camera/Mono BaseLink 配置必须一致 | 变化后重跑对应 BaseLink 阶段 | 配置变化要求新批次 |
| workflow profile 版本必须一致 | 版本变化后预检并重跑当前阶段 | 版本变化要求新批次或显式迁移 |
| 同名/同路径数据集不能原地变化 | 重新生成指纹并重跑该阶段及其下游 | 原地变化拒绝，要求新时间目录 |
| 已绑定数据集不能消失 | binding 更新为空，对应阶段等待新数据 | 消失时拒绝继续并要求恢复/替换 |
| pending 重标定期间输入必须固定 | 放弃旧 pending 计划，按当前输入重新计算受影响阶段 | pending 输入变化时拒绝继续 |
| state 中机器批次绝对路径必须一致 | 机器名与批次名一致时允许主机/Docker路径迁移 | 仅允许经过验证的显式迁移 |

## 3. 继续保留的硬安全检查

以下规则与算法是否收敛无关，移除会造成数据损坏、并发覆盖或越界访问，因此测试阶段
也继续生效：

- task、result、state 等文档的 `schema_version` 解析契约；软件版本可切换不代表可以
  把未知格式的状态文件当作当前结构读取；
- 同一批次的 workflow 文件锁，禁止两个进程同时写结果；
- 数据集、result、task、state、cache 和受管输出的符号链接检查；
- 所有受管路径必须位于自己的根目录，禁止路径逃逸；
- 数据集结构、相机/IMU 组成、时间戳和任务输入契约检查；
- 求解开始后再次检查输入，求解期间数据变化时拒绝发布结果；
- Camera–IMU/BaseLink 求解期间上游相机结果变化时拒绝发布；
- 新结果必须先完整求解和验证，再替换既有正式结果；
- 受管输出存在未知文件、损坏交付或不匹配 checkpoint 时不静默删除；
- state 和 calib_params 使用原子写入，失败时保留可诊断状态。

## 4. 测试阶段使用约束

- 同一批次允许修改程序、模式、模板、BaseLink 参数或同名数据内容后重新运行；
- 变化会触发受影响阶段重新求解，不代表旧结果仍可追溯；
- 每次用于对比的关键结果应由测试人员另行归档，不能把当前 `result/` 当成生产证据；
- 求解运行期间仍不得查看、同步或编辑会写入采集目录的文件；
- 不得手工编辑 state、checkpoint 或受管结果来绕过剩余硬安全检查。

## 5. 收敛后恢复条件

恢复产线防护前至少完成：

1. 普通双目、Rolling Shutter 双目、Camera–IMU、BaseLink 和单目分支均达到验收标准；
2. 重复采集与固定参数测试证明结果稳定；
3. 软件、profile、数据集和模式变化的拒绝/迁移测试全部恢复；
4. Docker、原生 Ubuntu 和正式安装包使用相同的软件 provenance；
5. 文档重新规定“一个批次绑定一套不可变输入与软件”；
6. 将 `_STRICT_PROVENANCE` 改回 `True`，重新 configure/build 并执行完整 `check`。

恢复时不得关闭第 3 节的硬安全检查，也不得通过手工修改历史 state 伪造兼容性。
